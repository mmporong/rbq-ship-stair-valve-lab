# 닫힌 밸브 구간의 보행 순서 변경 검증

이 디렉터리는 고정 50도·19cm 계단과 닫힌 candidate 4 밸브 조건에서, 명목상 112.20초 RL 스윙을 `RR 먼저 → 네 발 지지 몸체 이동 → RL` 순서로 바꾼 독립 구간 진단을 보존한다. 명목 계획과 대안 모두 예정 착지 156회와 최종 지지면 멀티셋을 유지한다.

## 정역학 계획 결과

- 결과: `verified_reorder`
- 20ms 간격 526표본, 총 10.5초
- 네 발 handoff와 세 발 swing 유지
- 최대 토크 비율 0.482252
- 충돌 활성 geom만 검사했을 때 레버 접촉 0표본
- 레버와의 최소 거리 2.511mm, 해당 pair의 합산 margin 1mm
- 두 손가락 qpos를 모든 표본에서 각각 0.04m로 유지

이 결과는 계획 자세의 정역학·접촉 검사 통과만 뜻한다.

## MuJoCo 동역학 재생 결과

같은 9키 track을 `transition.execute` force mode의 MuJoCo 1ms 적분과 measured-state QP+PD로 재생했다. 시작 시 밸브 hinge를 90도로 한 번 설정하고 qvel은 0으로 두었으며, 0.42초 settling 뒤 움직였다. 실행 중 `qpos`, `qvel`, `act`, mocap을 덮어쓰지 않았고 외력도 넣지 않았다.

손가락은 각각 0.04m 열린 상태에서 시작해 5ms마다 물리 actuator로 열린 상태를 유지했다. 10,500 물리 표본의 실측 aperture는 0.0798326~0.07999999m였고, 최소 기준 0.07975m를 충족했다.

동역학 판정은 `dynamic_failed`다. 이 구간의 시작을 0초로 두었다. 결과 JSON의 `time_s`는 명령 시각이고, 해당 명령을 적용한 뒤 측정한 힘·자세의 시각은 1ms 뒤다. 아래 두 시각을 원시 배열의 같은 행에서 대조했다. [사건별 표본 인덱스와 시각](inputs.json)

| 관측 사건 | 명령 시각 | 물리 스텝 종료 시각 |
|---|---:|---:|
| 오른쪽 뒷발 지지력 1N 미만 | 3.520초 | 3.521초 |
| 몸통 추종 오차 30mm 초과 | 6.972초 | 6.973초 |
| 레버 첫 접촉 101.419N | 7.332초 | 7.333초 |
| 힘 분배 계산 첫 실패 | 8.160초 | 8.161초 |
| 힌지 각도 89° 미만 | 9.198초 | 9.199초 |
| 왼쪽 뒷발이 예정된 5단을 벗어나 왼쪽 측판에 접촉 | 9.896초 | 9.897초 |

전체 구간에서 QP 실패는 164 tick, 최대 몸체 추종 오차는 116.923mm, 최대 기울기 추종 오차는 27.637도였다. 구간 말 최대 발 XY 오차는 0.69997m다. 원시는 `dynamic-result.raw.npz`에 10,500표본으로 보존했다.

## 반복성과 출처

`OPENBLAS_NUM_THREADS=1`, `OMP_NUM_THREADS=1` 환경에서 같은 고정 입력으로 두 번 실행했으며 모든 원시 배열이 바이트 수준에서 일치했다. 두 원시 파일의 SHA-256은 모두 `5a1843010b243a8d368fafc6a979abf2da685fcdb0008a0f1635f67764ef8a10`이다. 두 번째 원시는 임시 경로에서 비교한 뒤 공개 패키지에 중복 보존하지 않았다.

`fingerprint.json`은 실행 입력·결과·실행기 소스·route 입력·설정·RBQ 자산 lock과 실제 자산 SHA를 기록한다. 재현 명령과 고정 런타임 버전은 `inputs.json`에 있다. 출력과 companion 파일이 이미 있으면 CLI는 덮어쓰기를 거부한다.

## 한계

이 검증은 저장된 112.02초 자세에서 시작한 독립 구간 진단이다. 바닥에서 해당 초기 자세까지 도달할 수 있음을 증명하지 않으며, 전체 계단-밸브 임무 성공으로 해석하면 안 된다. 과거의 `qpos=0` 닫힌 손 실행은 유효 증거에서 제외했고, 보존용 해시만 `superseded-closed-hand.json`에 남겼다.
